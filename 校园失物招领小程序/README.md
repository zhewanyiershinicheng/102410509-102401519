# 校园失物招领小程序

一个面向校园场景的轻量级「失物招领」网页小程序。它把分散在班级群、宿舍群、朋友圈里的寻物 / 招领信息集中到一处，支持浏览、搜索、发布与管理，帮助同学们更快地找到遗失物品、归还拾获物品。

> 本项目是一个**移动端风格的纯前端单页应用**，使用原生 HTML / CSS / JavaScript 编写，无需后端、无需安装依赖，**双击 `index.html` 即可运行**。

---

## 一、功能特性

- **首页浏览**：按「全部 / 寻物 / 招领」筛选，按时间倒序展示最新信息。
- **关键词搜索**：按物品名称、地点、描述、类别关键词实时搜索，支持类型 + 类别组合筛选。
- **发布信息**：选择「我要寻物 / 我已拾获」，填写名称、类别、时间、地点、描述、图片、联系方式与昵称。
- **详情与联系**：查看图片、描述、时间、地点、发布者与联系方式，支持一键复制联系方式、识别手机号直接拨号。
- **状态管理**：发布者可将自己的信息标记为「已找到」、关闭或重新打开。
- **我的发布**：集中管理本人发布的信息（编辑 / 标记已找到 / 关闭 / 删除），并统计数量。
- **数据持久化**：所有数据保存在浏览器 `localStorage`，刷新、关闭页面后不丢失。

### 信息字段

| 字段 | 说明 |
| --- | --- |
| 类型 | 寻物（丢失） / 招领（拾获） |
| 物品名称 | 如「校园卡」「蓝色折叠雨伞」 |
| 类别 | 校园卡 / 钥匙 / 水杯 / 雨伞 / 耳机 / 书籍 / 电子设备 / 其他 |
| 时间 | 丢失 / 拾获时间 |
| 地点 | 教学楼、图书馆、食堂等校园场所 |
| 描述 | 物品外观、特征、经过等补充说明 |
| 图片 | 可选，上传后自动压缩并保存在本地 |
| 联系方式 | 手机号 / 微信号 / QQ 号 |
| 昵称 | 发布者昵称（默认「匿名同学」） |
| 状态 | 进行中 / 已找到 / 已关闭 |

## 三、使用说明

### 1. 运行方式

**方式一：直接打开（推荐，最简单）**

用浏览器（推荐 Chrome / Edge）双击打开 `index.html` 即可使用。

**方式二：本地静态服务器（可选）**

如果你习惯用本地服务器，在项目根目录执行：

```bash
# Python 3
python -m http.server 8080

# 或 Node.js
npx serve .
```

然后访问 `http://localhost:8080`。

> 项目为纯前端实现，不依赖任何后端服务或构建工具；两种方式功能完全一致。

### 2. 页面导航

应用底部固定有三个入口：

- **首页**：浏览全部最新信息。
- **＋ 发布**（中间圆形按钮）：进入发布页。
- **我的**：查看和管理本人发布的信息。

点击任意信息卡片即可进入**详情页**；详情页左上角箭头返回上一页。

### 3. 查找物品（查看 → 详情 → 联系）

1. 进入首页，通过「全部 / 寻物 / 招领」切换筛选。
2. 点击顶部搜索框进入搜索页，输入关键词（如「校园卡」「雨伞」），可叠加类型与类别筛选。
3. 点击感兴趣的卡片查看详情。
4. 在详情页点击「复制」保存发布者联系方式，若为手机号可直接「拨打」。

### 4. 发布物品（发布 → 成功 → 管理）

1. 点击底部「＋」进入发布页。
2. 选择类型：「我要寻物」或「我已拾获」。
3. 填写物品名称、类别、时间、地点，可选填描述、上传图片，填写联系方式与昵称。
4. 点击「发布」，弹出「发布成功」提示。
5. 进入「我的发布」可随时：**编辑**信息、**标记已找到**、**关闭**或**删除**。

### 5. 状态说明

| 状态 | 含义 |
| --- | --- |
| 进行中 | 信息仍在有效展示中 |
| 已找到 | 物品已找到 / 失主已联系上 |
| 已关闭 | 发布者手动关闭，不再在首页展示（可重新打开） |

## 四、技术说明

- **运行环境**：现代浏览器（Chrome / Edge / Safari / Firefox），移动端与桌面端均可。
- **技术栈**：原生 HTML + CSS + JavaScript，零构建、零运行时依赖。
- **第三方库**：仅引入 `normalize.css v8.0.1`（MIT 协议，本地化存放于 `css/vendor/`）。
- **数据存储**：`localStorage`，键为 `lf_items_v1`（JSON 数组）与 `lf_device_id_v1`（设备标识）。
- **“我的发布”识别**：每台设备首次打开时生成一个 `deviceId`，发布信息会记录该标识，用于在「我的发布」中过滤出本人发布的内容。
- **图片处理**：上传图片经 canvas 压缩（最长边 900px、JPEG 质量约 0.72）后以 dataURL 存入本地，避免超出 `localStorage` 容量。
- **路由**：基于 `location.hash` 的轻量路由（`#/`、`#/search`、`#/publish`、`#/publish/edit/:id`、`#/detail/:id`、`#/my`）。

### 数据字段（示例）

```json
{
  "id": "唯一标识",
  "type": "lost | found",
  "name": "物品名称",
  "category": "类别",
  "time": "ISO 时间字符串",
  "location": "地点",
  "description": "描述",
  "image": "图片 dataURL 或空字符串",
  "contact": "联系方式",
  "nickname": "发布者昵称",
  "status": "open | resolved | closed",
  "deviceId": "发布设备标识",
  "createdAt": 1234567890
}
```

## 五、常见问题

**Q1：换一台电脑 / 换个浏览器，之前发布的信息还在吗？**

不在。数据保存在当前浏览器的 `localStorage` 中，仅对同一浏览器有效。若需要多人共享数据，需接入后端服务（本项目按需求刻意省略了后台）。

**Q2：如何清空数据、恢复到初始状态？**

在浏览器开发者工具（F12）的 Console 中执行：

```js
localStorage.removeItem('lf_items_v1');
localStorage.removeItem('lf_seeded_v1');
```

刷新页面后会重新写入示例数据。

**Q3：为什么「我的发布」里没有看到示例信息？**

示例信息（用于演示浏览与搜索）的 `deviceId` 为 `demo`，不属于当前设备，因此不会出现在「我的发布」中。你发布的信息会出现在这里。

**Q4：上传图片后为什么不显示？**

图片会被压缩为 JPEG 后保存；若图片格式异常或文件过大，可换一张 JPG/PNG 再试。
