# 校园失物招领小程序

一个面向校园场景的轻量级「失物招领」网页小程序。它把分散在班级群、宿舍群、朋友圈里的寻物 / 招领信息集中到一处，支持浏览、搜索、发布与管理，帮助同学们更快地找到遗失物品、归还拾获物品。

> 本项目为**前后端分离**架构：
> - **前端**：移动端风格的 SPA，原生 HTML / CSS / JavaScript 编写（无构建工具）。
> - **后端**：Python 标准库实现的 REST 服务（`server.py`），使用 SQLite 持久化数据，**零第三方依赖，可实际部署**。

---

## 一、功能特性

- **首页浏览**：按「全部 / 寻物 / 招领」筛选，按时间倒序展示最新信息。
- **关键词搜索**：按物品名称、地点、描述、类别关键词实时搜索，支持类型 + 类别组合筛选。
- **发布信息**：选择「我要寻物 / 我已拾获」，填写名称、类别、时间、地点、描述、图片、联系方式与昵称。
- **详情与联系**：查看图片、描述、时间、地点、发布者与联系方式，支持一键复制联系方式、识别手机号直接拨号。
- **状态管理**：发布者可将自己的信息标记为「已找到」、关闭或重新打开。
- **我的发布**：集中管理本人发布的信息（编辑 / 标记已找到 / 关闭 / 删除），并统计数量。
- **数据持久化**：数据保存在后端 SQLite 数据库（`lostfound.db`），多端共享、重启不丢失。

### 信息字段

| 字段 | 说明 |
| --- | --- |
| 类型 | 寻物（丢失） / 招领（拾获） |
| 物品名称 | 如「校园卡」「蓝色折叠雨伞」 |
| 类别 | 校园卡 / 钥匙 / 水杯 / 雨伞 / 耳机 / 书籍 / 电子设备 / 其他 |
| 时间 | 丢失 / 拾获时间 |
| 地点 | 教学楼、图书馆、食堂等校园场所 |
| 描述 | 物品外观、特征、经过等补充说明 |
| 图片 | 可选，上传后压缩为 JPEG 并随信息保存到后端 |
| 联系方式 | 手机号 / 微信号 / QQ 号 |
| 昵称 | 发布者昵称（默认「匿名同学」） |
| 状态 | 进行中 / 已找到 / 已关闭 |

## 三、使用说明

### 1. 启动后端（必做）

本项目数据由后端提供，**需先启动后端**。在项目根目录执行：

```bash
# 使用系统 Python（推荐 3.8+，仅用标准库，无需安装任何依赖）
python server.py

# 指定端口（默认 8765）
python server.py 8000
```

启动成功后会打印：

```
校园失物招领后端已启动:
  本机访问   http://127.0.0.1:8765/
  局域网访问 http://<本机IP>:8765/
  API 示例   http://127.0.0.1:8765/api/items
```

> 首次启动会自动创建 `lostfound.db` 并写入若干示例信息，方便直接体验。

### 2. 打开小程序

浏览器访问 **http://127.0.0.1:8765/** 即可使用。

- 移动端体验：用手机浏览器访问「局域网访问」地址（需与电脑同一网络）。
- 注意：不要用 `file://` 直接双击 `index.html`，否则前端无法请求到后端 API。

### 3. 页面导航

底部固定三个入口：

- **首页**：浏览全部最新信息。
- **＋ 发布**（中间圆形按钮）：进入发布页。
- **我的**：查看和管理本人发布的信息。

点击任意信息卡片进入**详情页**；详情页左上角箭头返回上一页。

### 4. 查找物品（查看 → 详情 → 联系）

1. 进入首页，通过「全部 / 寻物 / 招领」切换筛选。
2. 点击顶部搜索框进入搜索页，输入关键词（如「校园卡」「雨伞」），可叠加类型与类别筛选。
3. 点击感兴趣的卡片查看详情。
4. 在详情页点击「复制」保存发布者联系方式，若为手机号可直接「拨打」。

### 5. 发布物品（发布 → 成功 → 管理）

1. 点击底部「＋」进入发布页。
2. 选择类型：「我要寻物」或「我已拾获」。
3. 填写物品名称、类别、时间、地点，可选填描述、上传图片，填写联系方式与昵称。
4. 点击「发布」，弹出「发布成功」提示。
5. 进入「我的发布」可随时：**编辑**信息、**标记已找到**、**关闭**或**删除**。

### 6. 状态说明

| 状态 | 含义 |
| --- | --- |
| 进行中 | 信息仍在有效展示中 |
| 已找到 | 物品已找到 / 失主已联系上 |
| 已关闭 | 发布者手动关闭，不再在首页展示（可重新打开） |

## 四、后端 API 说明

前后端通过 JSON 接口通信，接口前缀为 `/api`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/items` | 查询列表，可选参数：`type`(lost/found)、`category`、`kw`(关键词)、`device_id` |
| POST | `/api/items` | 发布一条信息（请求体为完整信息 JSON） |
| GET | `/api/items/<id>` | 查询单条信息 |
| PUT | `/api/items/<id>` | 更新信息（请求体为需要修改的字段） |
| DELETE | `/api/items/<id>` | 删除信息 |

示例：

```bash
# 查询全部
curl http://127.0.0.1:8765/api/items

# 按关键词搜索
curl "http://127.0.0.1:8765/api/items?kw=校园卡"

# 发布一条招领信息
curl -X POST http://127.0.0.1:8765/api/items \
  -H "Content-Type: application/json" \
  -d '{"id":"t1","type":"found","name":"校园卡","category":"校园卡","time":"2025-01-01T08:00:00.000Z","location":"图书馆","contact":"13800000000","nickname":"同学"}'
```

### 数据字段（JSON）

```json
{
  "id": "唯一标识",
  "type": "lost | found",
  "name": "物品名称",
  "category": "类别",
  "time": "ISO 时间字符串",
  "location": "地点",
  "description": "描述",
  "image": "图片 dataURL 或空字符串",
  "contact": "联系方式",
  "nickname": "发布者昵称",
  "status": "open | resolved | closed",
  "deviceId": "发布设备标识",
  "createdAt": 1234567890
}
```

## 五、技术说明

- **前端**：原生 HTML + CSS + JavaScript，单页应用（hash 路由），移动端风格。
- **后端**：Python 标准库（`http.server` + `sqlite3`），零第三方依赖，任何安装了 Python 的机器都能部署。
- **数据库**：SQLite（`lostfound.db`），结构化存储、支持并发读与事务写入。
- **第三方库**：前端仅引入 `normalize.css v8.0.1`（MIT 协议，本地化存放）。
- **“我的发布”识别**：每台设备首次打开时生成一个 `deviceId`（存于浏览器 localStorage），发布信息会记录该标识，用于在「我的发布」中过滤出本人发布的内容。正式上线如需严格身份，可在后端接入登录鉴权替换 `deviceId`。
- **图片处理**：上传图片经 canvas 压缩（最长边 900px、JPEG 质量约 0.72）后以 dataURL 存入数据库；生产环境可改为对象存储（OSS/COS 等）。
- **路由**：前端基于 `location.hash` 的轻量路由（`#/`、`#/search`、`#/publish`、`#/publish/edit/:id`、`#/detail/:id`、`#/my`）。

## 六、常见问题

**Q1：打开页面提示「无法连接服务器」？**

说明后端没启动。请在项目根目录执行 `python server.py`，再刷新页面。也不要直接双击 `index.html` 打开（`file://` 协议无法访问后端 API）。

**Q2：如何清空数据、恢复到初始状态？**

停止后端，删除项目根目录的 `lostfound.db` 文件，再重新执行 `python server.py`，即可自动重建数据库并写入示例数据。

**Q3：为什么「我的发布」里没有看到示例信息？**

示例信息（用于演示浏览与搜索）的 `deviceId` 为 `demo`，不属于当前设备，因此不会出现在「我的发布」中。你发布的信息会出现在这里。

**Q4：换了浏览器 / 换了电脑，我之前发布的信息还能在「我的发布」看到吗？**

数据本身保存在后端数据库里（所有人都能浏览到）；但「我的发布」按浏览器本地的 `deviceId` 过滤，换设备后不会自动关联。正式部署可接入登录系统，用账号替代 `deviceId`。

**Q5：如何部署到服务器？**

把整个目录上传到服务器，安装 Python 3.8+，执行 `python server.py 80` 即可（如需 80 端口可能需要相应权限）。前端页面与接口同源托管，无需额外配置。
